A. Your code
int add(int a, int b) {
    return a + b;
}

int main() {

    int num1, num2;

    cin >> num1 >> num2;

    int sum = add(num1, num2);

}

Your question is:

Why do we have a and b? We already have num1 and num2. Can't I just write a and b in main()?

Answer:

YES! You absolutely can.

This program is also correct:

int add(int a, int b) {
    return a + b;
}

int main() {

    int a, b;

    cin >> a >> b;

    int sum = add(a, b);

}

✅ This will work exactly the same.

Then why did we use different names?

Because a and b inside add() are completely different variables from the variables inside main().

This is the most important concept.

Imagine two rooms

Think of your program like a house.

------------------------
|       main()         |
|                      |
| num1 = ?             |
| num2 = ?             |
------------------------

        calls

------------------------
|      add()          |
|                     |
| a = ?               |
| b = ?               |
------------------------

Notice something.

main() has its own variables.

add() has its own variables.

They live in different rooms.

Step-by-step execution

Suppose the user enters

10
20
Step 1

Inside main()

int num1, num2;

cin >> num1 >> num2;

Memory becomes

main()

num1 = 10
num2 = 20

Only main() knows these values.

Step 2

Now you call

add(num1, num2);

What does this mean?

It means

Take the value stored in num1 and send it to a.

Take the value stored in num2 and send it to b.

So now

main()

num1 = 10
num2 = 20

and

add()

a = 10
b = 20

Both functions now have their own variables.

Think of it like a delivery

Imagine you have two boxes.

In main():

num1
↓

10
num2
↓

20

When you call

add(num1, num2);

you are saying

Send the value of num1.

Send the value of num2.

The function receives them as

a = 10

b = 20

Notice:

num1

↓

10

────────► a
num2

↓

20

────────► b
Then the function runs
return a + b;

Now

a = 10

b = 20

So

10 + 20

↓

30

gets returned.

Back to main()

Now

int sum = add(num1, num2);

becomes

int sum = 30;

So

main()

num1 = 10

num2 = 20

sum = 30
Why not just remove a and b?

Imagine writing

int add(int num1, int num2)

instead.

This is perfectly legal.

int add(int num1, int num2) {
    return num1 + num2;
}

Then

int num1, num2;

cin >> num1 >> num2;

int sum = add(num1, num2);

works perfectly.

So why don't people always do that?

Because the names inside the function are local to the function.

Most programmers choose short names like

a
b
x
y

for small mathematical examples.

VERY IMPORTANT

The function does not care what the variable names are.

Look at these three calls.

Version 1
int num1 = 10;
int num2 = 20;

add(num1, num2);
Version 2
int first = 10;
int second = 20;

add(first, second);
Version 3
int apples = 10;
int oranges = 20;

add(apples, oranges);

All three send

10

20

to

a

b

The function doesn't know (or care) whether the values came from num1, first, or apples. It only receives two integers.

The biggest takeaway

When you write:

int add(int a, int b)

you are not declaring global variables named a and b.

You are saying:

"Whenever someone calls this function, I will receive two integers. Inside this function, I will refer to them as a and b."

That's why you can call:

add(num1, num2);
add(first, second);
add(apples, oranges);

and they all work.
